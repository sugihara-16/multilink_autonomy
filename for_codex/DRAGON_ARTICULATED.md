# DRAGONの両端センサ構成

2026-10-26実装。4リンクのlink1にLiDAR＋IMU、link4に単眼カメラを配置し、6個の関節角を選んで視野を変える、視野を選ぶ構成。2026-10-27に複数関節による大域的な視野探索へ拡張した。

## 起動

```bash
ros2 launch multilink_uas_bringup dragon_articulated.launch.py
```

既存の人工トンネルでGazebo画面を開き、離陸→初期化→準備運動2周期→初期の視野観測→90m飛行→着陸を行い、自動終了する。画面不要の検証には `headless:=true` を付ける。RViz・rosbag収録はなし。途中終了はCtrl+C。固定関節での飛行は `mode:=fixed`、ホバリングのみは `distance:=0`。`output:=...` を省略すると日時付きの出力先を作成する。

このlaunchは有限時間の検証用。通常の手動飛行や全方位の関節探索を起動するものではない。`distance` は0〜90mの範囲。既定の移動速度は0.5m/s。`speed:=0.3` のように変更できる。初期観測は40秒かけて3つのyaw関節を同時に開閉し、カメラで約180°の範囲を見る。固定条件も同じ初期観測の後、走行中だけ関節を固定する。

## センサと座標系

- 生成処理: `multilink_uas_bringup/native/dragon_articulated.py`。既存の `unipilot_gimbal.prepare(sensor_profile='native', imu_sampling='resolved', camera_far=1000)` からセンサ定義をコピーする。
- LiDAR: 10Hz、500×48、測距ノイズ標準偏差0.03m。UniPilotのIMUに対する位置・姿勢、走査範囲・測距範囲をそのまま引き継ぐ。
- IMU: 1000Hz。従来の200Hz定義から取得周期を上げる際の白色ノイズ密度補正、バイアス・相関時間もUniPilotの生成処理と共通。
- カメラ: 単眼480×270、20Hz。画角・内部パラメータ・クリップ距離・画像処理もUniPilotと共通。
- 飛行制御が磁気センサの接続を要求するため、UniPilotの元SDFにある磁気センサを使用する。SLAMには入力しない。DRAGON既定のIMU・カメラ・LiDAR・磁気・GPSセンサ定義は除去する。
- FCフレームをlink2からlink1に移す。LiDARはFCフレームに固定、カメラはlink4の `(0.10, -0.08, 0)` m、ローカル-y向き。カメラの回転と並進の両方が関節角に依存する。
- 起動ごとに `articulated_manifest.json` にセンサ設定の一致検査と初期座標変換を記録する。

## 推定と視野選択

Gazeboの実測関節角を画像時刻に補間し、URDFからカメラとIMUの相対位置・姿勢を計算する。指令角を計測値の代わりには使わない。

既存ROVIOのジンバル拡張は回転専用だったため、独立した `rovio-articulated` ビルドで並進にも対応した。特徴点の方向・距離、全状態との相互の共分散も変換し、IMU側の状態は動かさない。従来のUniPilot用バイナリは変更していない。

MIMOSAは現在採用している速度・傾き融合、IMUモデル、ノイズ設定を継承。DRPMはOFF。視野選択は現在のLiDAR情報とROVIOの特徴点・速度の共分散を使う。各候補のカメラ位置が異なることを予測計算に反映する。真値は飛行制御と事後評価だけに使用する。

関節候補はURDFの可動範囲（各軸±90°に停止余裕を加えた±89.43°）から生成する。現在の四角形から237候補へ到達する接続経路を作り、複数関節を同時に変化させる。さらに、現在姿勢の近くに複数関節を組み合わせた10°の候補を加える。関節速度は10°/s、加速度は20°/s²。形状と経路内部の近接、ローター配置の広がり、センサで観測した周囲の構造、視野の遮蔽を検査する。近接判定は近似形状であり、厳密なメッシュ干渉保証ではない。

視野選択では、ROVIOの特徴点と画像から追加した特徴点を地図に残す。追加点の深度は観測したLiDARまたは画像の三角測量から求める。方向ごとに点を残し、現在の画角だけで地図を埋めない。未観測方向に特徴を仮定したり、模様配置の正解を参照したりしない。

採点は、現在のLiDAR情報と視覚を組み合わせた並進不確かさの減少に基づく。ジンバルで使った相関付きの速度予測を主評価とし、観測済み地図の位置情報を補助にする。保持姿勢で正規化した `log(1+速度情報利得比) + 0.1*log(1+地図情報利得比) - 0.002*移動秒数`、切り替えに3%の改善を要求する。地図側は特徴点間の独立近似を含む計画用の評価で、推定器の共分散そのものではない。ジンバルv10と全く同じ候補生成・採点の実装ではない。

LiDARの地図照合情報が0.5秒以上更新されない場合、視野計画ではLiDAR情報をゼロとして有限の事前不確かさと視覚情報で観測を継続する。退化方向が分かった扱いにはしない。融合推定器の設定や重みは変えない。

LiDARを載せたFCの位置が既定の経路を通るよう、関節変形で動く重心位置を飛行指令で補償する。動力学による姿勢の揺れは残るため、「LiDARの世界姿勢が厳密に不変」とは扱わず、実測の揺れを報告する。

## ビルドと再検証

```bash
python3 /root/uas_native/active_perception/build_articulated_rovio.py
source /root/uas_native/env.sh
python3 /root/uas_native/active_perception/test_articulated_dragon.py
```

C++テストはROVIOの4種類の距離表現について、カメラの回転・並進の前後で特徴点の実空間位置、共分散、他状態との相互の共分散が保たれることを確認する。

起動時のROSサービス応答が欠落するとGazeboが無期限待ちになったため、外部 `gz_ros2_control` に応答待ちのタイムアウト・再試行を追加した。再適用用の差分は `native/dragon-control-description-retry.patch`、対象は `/root/ros2/aerial_robot_base_ws/src/gz_ros2_control`。変更後は同workspaceで `colcon build --packages-select gz_ros2_control --symlink-install` を実行する。

## 2026-10-27の90m比較

結果は `/root/uas_native/logs/dragon-global-20261027/report/index.html`。同じ人工トンネル24301、90m/0.5m/s、固定/偏向各1飛行。初期観測を除外し、追従開始時の位置・姿勢だけを合わせる。尺度補正なし。

| 推定器 | 固定・位置RMSE | 関節偏向・位置RMSE |
|---|---:|---:|
| ROVIO | 928.81m | 24.52m |
| ROVIO＋MIMOSA | 51.99m | 18.26m |

走行中の関節の変化幅は最大65.10°、カメラの姿勢全体（画像の回転を含む）は初期から最大41.95°、光軸の偏向は最大30.61°。カメラ位置の変化幅はX/Y/Zそれぞれ0.293/0.252/0.423m。33回の目標選択中15回は大域候補、28回は複数関節を2°以上変える目標だった。

融合の残る誤差は主にトンネル軸方向の過小評価。固定より良い結果だが、精度改善を終えた状態ではない。過去のUniPilotジンバルの同配置の試行は融合5.50mで、今回のDRAGONはその値には届いていない。取り付け方向・位置、初期観測と採点方式にも差がある。

現在の制約は、候補/経路計算が重く判断間隔が中央値2.66秒、LiDARの世界姿勢が関節動作中に最大7.06°変動したこと。LiDAR照合情報が新鮮だったのは70判断中33、残る37判断は視覚による観測継続。全方位での飛行、厳密なメッシュ干渉、実機は今回未検証。検証用プロセスは全て停止済み。
