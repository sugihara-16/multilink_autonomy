# ROVIO校正・MIMOSA＋DRPM・FAST-LIVO2画像更新の比較（2026-10-04）

今回の2例では、FAST-LIVO2の画像更新が良好な位置精度と推定の安定性に大きく寄与した。ROVIOの実測誤差で校正したMIMOSA＋DRPMは以前の大きな姿勢発散を起こさなくなったが、位置誤差は約4.4m残り、同じ校正を使ったDRPMなしより改善しなかった。

## 計測条件
- 前回と同じ単眼link3、同じLiDAR/IMU、同じrun2a_end（49.48秒）とrun1_tail_a2_prefix（200.18秒）の追従区間。ROVIO単独の前回の生推定CSVを再利用して特性を測定。入力のSHA256をcalibration.jsonへ保存。
- 校正用と評価用の飛行を入れ替える2分割評価。一方のrunの50ms相対姿勢誤差から作った固定の6×6行列を他方に適用。自己評価データへの合わせ込みや融合結果を見た重み探索はしない。
- 相対姿勢誤差はGTSAM BetweenFactorと同じLog(Z_vio^-1 Z_truth)、回転rad→並進mの順。誤差の平均を差し引かない二次モーメントを使い、偏りも含める。真値によるodometry補正は行わない。
- 軸間の関係を含む行列をMIMOSAの外部odometry因子に適用。ROVIOの出力共分散の単純流用ではない。共通IMUの相関、時間相関、動的な不確かさ変化の補正は未実装。
- FAST-LIVO2の標準LIOモードはimg_en=0で画像topicを読まない。別の対照は画像と同じ時刻処理を維持してhandleVIOだけを呼ばない。さらに、準備段階を画像ありで動かし追従開始以降だけhandleVIOを止める追加対照を実施。
- すべて初期化用に追従開始前のセンサーも処理。評価は追従のみ。開始時に一度だけ位置・姿勢を真値へ整合、スケール補正や全軌道当てはめはしない。共通10Hzの元LiDAR時刻に推定・真値を補間し、外挿しない。
- 元の推定CSVは元の整数ns時刻のまま保存。誤差CSVは補間評価の時刻をevaluation_stamp_nsと明記。今回の出力に新たな画像・点群は保存していない。

## ROVIOの特性

50ms相対姿勢誤差の軸別RMSE。これは絶対姿勢のRMSEではない。並進X方向の誤差がY/Zより大きく、時間的な偏りも強い。

| 測定飛行（他方の校正に使用） | 回転X/Y/Z [deg] | 並進X/Y/Z [mm] |
|---|---|---|
| run2a_end | 0.000475 / 0.001741 / 0.000137 | 9.880 / 0.224 / 0.338 |
| run1_tail_a2_prefix | 0.000201 / 0.001220 / 0.000111 | 7.571 / 0.352 / 0.286 |

並進誤差の隣り合う時刻間の相関係数は0.74〜0.92。時間間隔を1秒へ広げるとX誤差は約114〜155mmとなる。独立した白色雑音だけでは表現できない。0.05/0.1/0.5/1秒の平均・標準偏差・RMSE・95%点・時間相関をcalibration.jsonに保存した。

他方の飛行に対する6次元95%楕円内の割合は92.2% / 84.2%。これは共分散が全条件で整合していることを保証する校正ではない。軸の相関を残す数値的な正則化を実装したが、両校正行列とも固有値の切り上げは0件だった。

## 結果の解釈

### 校正したROVIOを使うMIMOSA＋DRPM
- 以前の大きな姿勢発散はなくなり、姿勢RMSEは0.159° / 0.225°。旧DRPM条件は5.241° / 122.990°。
- 位置RMSEは4.400m / 4.454m。同じ校正を使ったDRPMなしは0.511m / 4.256mで、DRPMによる位置精度の改善はなかった。
- 手動で回転σだけ0.02°にした過去の感度試験とは異なり、今回は並進を含む六軸を別runの実測から固定した。過去の感度試験の方が一部の精度が高くても、その値へ再調整はしていない。
- DRPMは前回と同じ「情報量の重み付け」のグラフへの移植。原論文の修正量を抑える処理すべての再現ではなく、今回もDRPM一般の優劣とは結論しない。

### FAST-LIVO2の画像更新
- 標準LIOモードも、画像更新のみを除いた同一時刻の対照も発散した。最初から画像なしの短いrunは追従開始より約22秒前、離陸後に高度が落ち着く段階ですでに位置誤差5mを超えていた。向き合わせはその後なので、「向き合わせ中」とした途中説明は真値確認後に訂正した。
- 短いrunの準備段階での破綻が比較を支配しているため、追従開始後だけ画像を止める対照を追加。その場合でも短いrunは位置RMSE13.768m / 姿勢2.708°であり、画像ありの0.035m / 0.662°から悪化した。長いrunはこの追加対照でも途中で発散した。
- 追加対照の追従開始前の軌跡は画像あり基準と最大0.0117m / 0.129°、0.00874m / 0.0657°の差。並列数値計算を含む別試行なので、状態のビット単位の同一性は主張しない。
- 画像OFFのログでは点群の有効対応が0となる行が長く続く。入力欠落による停止ではなく、推定出力を継続しながら位置が大きく逸脱している。対応が失われる最初の原因の分解まではしていない。
- 通常MIMOSA LIOよりFAST-LIVO2のLiDAR/IMU処理だけが強い、という結果ではなかった。この設定・2例では画像更新が精度と安定性を支えている。ただしtight couplingと別の融合方式の差そのものは分離していない。
- 長いrunの通常MIMOSA LIOは位置RMSE1.108mでも姿勢RMSE56.279°。位置の数値だけで良好と判定しない。

位置誤差5mを初めて超えた時刻はfailure_onset.jsonに保存。ここだけは初期の最初の姿勢へ整合して全入力期間を調べ、追従開始時に整合する本評価と区別した。5mは診断用の表示基準で、アルゴリズムの内部退化判定ではない。

## 検証・成果物
